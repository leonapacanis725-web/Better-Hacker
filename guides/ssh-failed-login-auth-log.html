BEGINNER LINUX SECURITY GUIDE

How to Find Failed SSH Logins in Linux auth.log

Linux authentication logs can help defenders understand when accounts were used and whether repeated login failures deserve investigation. This guide uses a local training system or authorized log sample only.

1. Know where authentication events are recorded

On Debian- and Ubuntu-based systems, authentication events are commonly written to /var/log/auth.log. Other distributions may use a different file or the system journal. Confirm the logging configuration before assuming a file exists.

2. Search for failed SSH authentication

On a system you administer, a read-only search can help locate relevant records:

sudo grep -i "failed password" /var/log/auth.log

grep searches text; -i ignores letter case. The command reads matching log lines and does not change the log.

3. Review the evidence, not just the count

For each record, note the timestamp, account name, source address, authentication method, and whether a later successful login appears. Group related events into a timeline. A burst of failures may be worth investigating, but failed attempts alone do not prove an account was compromised.

4. Document a defensible finding

  • Record the log source and time range reviewed.
  • Quote or preserve relevant timestamps and source addresses.
  • Compare the activity with approved maintenance and known users.
  • State what is observed separately from what is inferred.
  • Follow the organization's incident process; preserve evidence before approved containment.
