BEGINNER WINDOWS SECURITY GUIDE

Windows Event IDs 4624, 4625, and 1102 Explained

Windows Security logs record authentication and audit events. These three IDs are useful clues, but an event should always be interpreted with its surrounding context.

Event ID 4624 — successful logon

Windows records a successful account logon as Event ID 4624. Review the account, logon type, timestamp, workstation or source network address when present, and the system where the event was recorded. A successful logon is not automatically suspicious.

Event ID 4625 — failed logon

Event ID 4625 records a failed logon. Review the target account, failure reason/status, source address, and frequency. Repeated failures may result from a mistyped password, a stale service credential, or unauthorized attempts. Correlate before drawing a conclusion.

Event ID 1102 — audit log cleared

Event ID 1102 indicates that the Windows Security audit log was cleared. Verify who performed the action, when it occurred, whether maintenance was approved, and whether related records exist on a central log collector. The event is important, but it does not by itself identify motive.

Build a short investigation timeline

  1. Capture the host name and time range.
  2. Group 4625 failures by account and source.
  3. Check whether a 4624 success follows the failures.
  4. Look for 1102 and other related changes.
  5. Compare with approved work and document uncertainty.

In an authorized PowerShell session, a read-only example for recent failed logons is:

Get-WinEvent -FilterHashtable @{LogName="Security"; Id=4625} -MaxEvents 20
