          LESSON 01

          Cybersecurity Fundamentals

          Start with the core ideas every cybersecurity learner should understand: threats, vulnerabilities, risk, authentication, authorization, and basic security principles.

          Lesson guide

          Prerequisites: No prerequisites—this is the starting point.

          Learning objectives

          Explain the CIA triad; distinguish threats, vulnerabilities, and risk; apply authentication, authorization, least privilege, and defense in depth.

          Why this matters in cybersecurity

          These ideas give defenders a shared language for describing what must be protected and how controls reduce risk.

          View your Learner Dashboard

          1. The CIA Triad

          The CIA Triad describes three major goals of cybersecurity.

          Confidentiality Protects information from unauthorized access.
          Integrity Helps ensure information is accurate and has not been improperly changed.
          Availability Helps make sure systems and data are available when needed.

          2. Threats, Vulnerabilities, and Risk

          A threat is something that could cause harm. A vulnerability is a weakness that could be exploited.

          Risk is the potential impact created when a threat can take advantage of a vulnerability.

          3. Authentication and Authorization

          Authentication verifies who a user is.

          Authorization determines what that user is allowed to access after their identity has been verified.

          4. Least Privilege

          The principle of least privilege means users, programs, and systems should receive only the access they need to perform their required tasks.

          Limiting unnecessary access can reduce the damage caused by mistakes, compromised accounts, or malicious activity.

          5. Defense in Depth

          Defense in depth uses multiple layers of security instead of relying on a single protective control.

          These layers can include passwords, multi-factor authentication, firewalls, antivirus tools, monitoring, permissions, and backups.

          Try It — safe analysis

          A teammate needs one report. Compare granting access to that report with granting administrator access. Which choice follows least privilege, and why?

          🧠 Knowledge Check

          What security principle means giving users only the access they need?

          Lesson recap

          Security protects confidentiality, integrity, and availability. Risk connects threats, weaknesses, and impact. Authentication proves identity; authorization controls access.

          Recommended next activity: Continue to Networking

          BEGINNER LESSON

          Networking Fundamentals

          Networking is a core cybersecurity skill. Learn how IP addresses, ports, DNS, TCP, UDP, and HTTP help devices communicate, then use fictional traffic records to practice recognizing expected connections and spotting activity that may need closer review.

          Lesson guide

          Prerequisites: Recommended first: Cybersecurity Fundamentals.

          Learning objectives

          Describe devices, IP addresses, ports, DNS, TCP, and UDP; connect common ports to services; interpret simple network evidence.

          Why this matters in cybersecurity

          Defenders use network context to recognize expected services, investigate unusual connections, and configure controls.

          View your Learner Dashboard

          1. What is a Computer Network?

          A computer network is a group of devices that communicate and share information with each other.

          Networks can include computers, servers, phones, routers, switches, printers, and many other devices.

          2. IP Addresses

          An IP address identifies a device on a network. It allows devices to know where network traffic should be sent and received. 

          192.168.1.10

          3. Ports and Protocols

          Ports help identify services running on a device. Different network services commonly use different ports.

          22 SSH — secure remote access.
          53 DNS — translates domain names into IP addresses.
          80 HTTP — standard web traffic.
          443 HTTPS — encrypted web traffic.

          4. TCP and UDP

          TCP focuses on reliable communication and makes sure data arrives correctly and in order.

          UDP is faster and does not require the same delivery confirmation as TCP.

          Try It — safe analysis

          A simulated server lists 22/TCP, 53/UDP, and 443/TCP. Identify the likely service for each, then note that a port is a clue—not proof of the application.

          5. Knowledge Check

          Which port is commonly used for HTTPS?

          Lesson recap

          IP addresses locate devices; ports identify service endpoints; protocols define communication rules. TCP emphasizes reliable delivery, while UDP has less overhead.

          Recommended next activity: Continue to Linux

          Keep Building Your Skills

          Understanding networking will make tools such as Nmap, Wireshark, firewalls, and SIEM platforms much easier to learn.

          Linux Fundamentals

          Linux is widely used in cybersecurity, servers, cloud systems, and security tools. Learning the command line is an important foundation for building cybersecurity skills.

          Lesson guide

          Prerequisites: Recommended first: Cybersecurity Fundamentals and Networking.

          Learning objectives

          Navigate directories; identify read-only inspection commands; explain why permissions and careful command selection matter to defenders.

          Why this matters in cybersecurity

          Linux runs many servers and security tools. Safe command-line inspection lets defenders gather evidence without changing it.

          View your Learner Dashboard

          1. What is Linux?

          Linux is an operating system similar to Windows and macOS. It is widely used on servers and is common in cybersecurity environments.

          2. Basic Linux Commands

          pwd Shows your current directory.
          ls Lists files and folders.
          cd Changes your current directory.
          cat Displays the contents of a file.
          grep Searches text for a word or pattern.
          find Searches for files and directories.

          3. Example

          Imagine a file named flag.txt is stored in your current directory.

          To view the file, you could run:

          cat flag.txt

          Try It — safe analysis

          In a safe local training directory, read this simulated listing: -rw-r--r-- 1 learner learner 42 notes.txt. The leading dash means a regular file. Which read-only command would display it?

          4. Knowledge Check

          Which Linux command displays the contents of a file?

          Lesson recap

          Use pwd, ls, cat, and grep to orient and inspect. Confirm paths before running commands and avoid destructive changes during triage.

          BEGINNER LESSON

          Web Security Fundamentals

          Websites and web applications are common targets for attackers. Learning how web applications work and where vulnerabilities appear is an important cybersecurity skill.

          Lesson guide

          Prerequisites: Recommended first: Networking fundamentals.

          Learning objectives

          Describe browser-server requests; distinguish HTTP and HTTPS; recognize SQL injection, XSS, and broken access control; name defensive input-handling practices.

          Why this matters in cybersecurity

          Web applications often handle identities and sensitive data. Separating untrusted data from instructions reduces preventable compromise.

          View your Learner Dashboard

          1. What is Web Security?

          Web security is the practice of protecting websites, web applications, users, and data from attacks.

          Security professionals look for weaknesses that could allow attackers to steal information, access accounts, or manipulate an application.

          2. How Web Applications Work

          When you visit a website, your browser sends a request to a web server. The server processes the request and sends a response back to your browser.

          HTTP Protocol used for communication between browsers and web servers.
          HTTPS Encrypted version of HTTP used to protect web traffic.
          GET Common HTTP method used to request information.
          POST Common HTTP method used to send information to a server.

          3. Common Web Vulnerabilities

          Web applications can contain vulnerabilities when user input, authentication, permissions, or data are handled incorrectly.

          SQL Injection Unsafe input can interfere with database queries.
          XSS Cross-site scripting can allow malicious scripts to run inside another user's browser.
          Broken Access Control Users may be able to access information or actions they should not have permission to use.

          4. Why Input Validation Matters

          Applications should never automatically trust user input. Input should be checked and safely handled before it is processed by the application or database.

          Proper validation and secure coding practices can prevent many common web attacks.

          Try It — safe analysis

          Compare query + userInput with a parameterized query using a placeholder. Which design keeps the value separate from SQL instructions? This is analysis only—do not test real sites.

          5. Knowledge Check

          Which vulnerability can occur when unsafe user input is placed directly into a database query?

          Lesson recap

          Browsers exchange requests and responses with servers. Validate input, encode output for its context, parameterize database queries, and enforce authorization on the server.

          Recommended next activity: Continue to Cryptography

          Ready to Practice?

          You now know the foundations of web security. Continue into the Better Hacker labs to practice identifying common vulnerabilities.

          BEGINNER LESSON

          Cryptography Fundamentals

          Cryptography helps protect information from unauthorized access. It is used throughout cybersecurity to secure passwords, communications, files, and sensitive data.

          Lesson guide

          Prerequisites: Recommended first: Cybersecurity Fundamentals.

          Learning objectives

          Distinguish encryption, hashing, and encoding; explain plaintext, ciphertext, keys, and integrity checks; choose a control for a stated goal.

          Why this matters in cybersecurity

          Choosing the wrong mechanism can expose data: encoding provides no secrecy, and a hash is not recoverable encrypted data.

          View your Learner Dashboard

          1. What is Cryptography?

          Cryptography is the practice of protecting information by transforming or verifying data using mathematical techniques.

          Modern cybersecurity uses cryptography for confidentiality, integrity, authentication, and secure communication.

          2. Encryption

          Encryption transforms readable information called plaintext into an unreadable form called ciphertext.

          Plaintext The original readable information.
          Ciphertext The encrypted and unreadable form of the information.
          Key Information used by an encryption algorithm to protect or recover data.

          3. Hashing

          Hashing converts data into a fixed-size value called a hash. Unlike encryption, hashing is designed to be one-way.

          Hashes can help verify data integrity and are commonly used as part of secure password-storage systems.

          4. Encryption vs. Hashing

          Encryption Designed so authorized users can recover the original data using the proper key.
          Hashing Designed as a one-way transformation used for verification and integrity.

          Try It — safe analysis

          A recipient must recover a protected backup with an approved key. Choose encryption, hashing, or encoding and explain why the other two do not meet the goal.

          5. Knowledge Check

          Which security process transforms readable plaintext into unreadable ciphertext?

          Lesson recap

          Encryption protects confidentiality and is reversible with authorized key material. Hashing supports integrity and verification. Encoding only changes representation.

          Recommended next activity: Continue to Active Directory

          Ready to Practice?

          You now understand the basic difference between encryption and hashing. Continue into the Better Hacker labs to practice cryptography concepts.

          LESSON 06

          Active Directory Fundamentals

          Learn how Active Directory organizes users, computers, and groups in Windows domains. Explore authentication, permissions, least privilege, and why reviewing account or group changes helps protect an organization’s access boundaries.

          Lesson guide

          Prerequisites: Recommended first: Cybersecurity Fundamentals and Windows account concepts.

          Learning objectives

          Describe domains, domain controllers, users, groups, authentication, and permissions; apply least privilege to account administration.

          Why this matters in cybersecurity

          Active Directory can govern access across an organization, so unusual sign-ins, group changes, and excessive privileges deserve careful review.

          View your Learner Dashboard

          1. What is Active Directory?

          Active Directory (AD) is Microsoft's directory service used by organizations to manage users, computers, groups, and access to network resources.

          Instead of managing every computer separately, administrators can use Active Directory to manage many systems from a central location.

          2. Domains and Domain Controllers

          An Active Directory domain is a collection of users, computers, and other resources managed together.

          A Domain Controller (DC) is a server that runs Active Directory Domain Services and handles important tasks such as authentication.

          3. Users and Groups

          User accounts represent people who can sign in and access resources within the organization.

          Groups allow administrators to organize users and assign permissions to multiple people at once.

          4. Authentication and Permissions

          Authentication verifies who a user is. After authentication, permissions determine which files, systems, and resources that user can access.

          Proper permissions help prevent users from accessing information they do not need.

          5. Why Active Directory Security Matters

          Active Directory can control access to many important systems in an organization, which makes protecting it extremely important.

          Security teams monitor accounts, login activity, permissions, and administrative privileges for suspicious behavior.

          Try It — safe analysis

          A person changes departments. List two items to review: their group memberships and the resources those groups can access. Remove only access no longer required through an approved process.

          🧠 Knowledge Check

          What Active Directory object represents a person who can sign in to the network?

          Lesson recap

          Domains organize managed resources; domain controllers provide directory services; users represent identities; groups simplify permission assignment.

          Recommended next activity: Continue to SOC & SIEM

          LESSON 07

          SOC & SIEM Fundamentals

          Learn how Security Operations Center (SOC) analysts use Security Information and Event Management (SIEM) tools to collect and review logs, validate alerts, correlate events, and investigate suspicious activity with simulated evidence before recommending a proportionate response.

          Lesson guide

          Prerequisites: Recommended first: Networking, Linux, and Active Directory.

          Learning objectives

          Explain SOC and SIEM roles; identify useful log fields; distinguish an alert from a confirmed incident; outline safe investigation and response.

          Why this matters in cybersecurity

          Centralized evidence helps analysts correlate events, validate alerts, preserve context, and choose proportionate responses.

          View your Learner Dashboard

          1. What is a SOC?

          A Security Operations Center, or SOC, is a team responsible for monitoring an organization's systems and networks for suspicious activity and security threats.

          SOC analysts review alerts, investigate unusual behavior, and help respond to security incidents.

          2. What is a SIEM?

          SIEM stands for Security Information and Event Management.

          A SIEM platform collects security logs and events from many systems so analysts can search, analyze, and monitor activity from one place.

          3. Security Logs

          Logs record activity that happens on computers, servers, applications, and network devices.

          Login Logs Record successful and failed login attempts.
          Firewall Logs Record allowed and blocked network connections.
          System Logs Record important operating system events.

          4. Investigating Alerts

          When a SIEM creates an alert, an analyst investigates what happened and decides whether the activity is normal or potentially malicious.

          Analysts often examine who performed the activity, what happened, where it happened, and when it occurred.

          5. Incident Response

          If an investigation confirms a real security incident, the security team may contain the threat, remove malicious activity, recover affected systems, and document what happened.

          Try It — safe analysis

          A simulated alert shows 14 failed logins followed by a success from an unknown device. Identify the user, time, device, outcome, and one related log source you would check.

          🧠 Knowledge Check

          What type of platform collects and analyzes security logs from many different systems?

          Lesson recap

          A SOC monitors and responds; a SIEM centralizes and correlates events. Alerts require validation. Preserve evidence, scope impact, and follow an authorized response plan.

          LESSON 08

          Security Testing Fundamentals

          Learn the basics of authorized security testing, reconnaissance, vulnerability assessment, and responsible reporting.

          Lesson guide

          Prerequisites: Recommended first: the preceding seven core lessons.

          Learning objectives

          Explain authorization and scope; distinguish reconnaissance from vulnerability assessment; describe responsible evidence collection, reporting, and remediation.

          Why this matters in cybersecurity

          Testing without permission can be harmful and unlawful. A written scope protects systems, learners, and organizations while keeping work focused.

          View your Learner Dashboard

          1. What is Security Testing?

          Security testing is the process of checking systems, applications, or networks for weaknesses that could create security risks.

          The goal is to identify problems before attackers can take advantage of them.

          2. Authorization Comes First

          Security testing should only be performed on systems you own or have clear permission to test.

          Professional security testers work within an approved scope that defines what systems and techniques are allowed.

          3. Reconnaissance

          Reconnaissance is the process of gathering information about a target before deeper testing begins.

          IP Address Identifies a device on a network.
          Open Ports Can reveal services running on a system.
          Services Applications listening for network connections.

          4. Vulnerability Assessment

          A vulnerability assessment looks for known weaknesses, insecure settings, outdated software, and other security problems that may need to be fixed.

          5. Reporting and Remediation

          Finding a vulnerability is only part of the job. Security professionals document what they found, explain the risk, and recommend how the weakness can be fixed.

          Try It — safe analysis

          Review this simulated scope: “Training host 192.0.2.10; inventory scan only; 09:00–10:00 UTC.” Identify the allowed asset, technique, and time window. Do not scan any real system.

          🧠 Knowledge Check

          What must you have before performing security testing on a system?

          Lesson recap

          Authorization comes first. Stay inside scope, minimize impact, document evidence, communicate risk clearly, and verify remediation safely.

          SUPPLEMENTAL LESSON

          Computer Fundamentals & Security Tools

          A computer is a collection of hardware managed by an operating system. Defenders learn what “normal” looks like before deciding that an event is suspicious.

          Learning objectives

          • Distinguish hardware, operating systems, applications, and processes.
          • Explain why files, processes, network connections, and logs are useful evidence.
          • Select safe, read-only tools for initial observation.

          Why this matters in cybersecurity

          Alerts refer to processes, accounts, files, and connections. Understanding those building blocks helps you verify an alert without changing evidence or interrupting a healthy system.

          Important terminology

          Operating system (OS)
          Software that manages hardware and provides services to applications.
          Process
          A running instance of a program, identified by a process ID (PID).
          Log
          A time-ordered record of events.
          Telemetry
          Measurements collected from systems for monitoring and analysis.

          From components to evidence

          Hardware provides CPU, memory, storage, and network interfaces. The OS schedules processes and enforces permissions. Applications use those OS services. A defender correlates evidence across these layers instead of trusting one clue.

          Example: a simulated alert names PID 2410. The PID identifies a running process, while its executable path, parent process, user, and network activity provide context.

          Safe first-look tools

          In an authorized training system, read-only commands such as ps (processes), whoami (current identity), and ss -tuln (listening network sockets) can help you observe state. Do not terminate processes, delete files, or change permissions during initial triage.

          SIMULATED OUTPUT
PID   USER      COMMAND
2410  learner   browser

          Try It: analyze the clue

          A simulated alert only says “PID 2410 is suspicious.” Name two pieces of context you would collect before deciding. Suggested evidence includes the process name/path, parent process, user, start time, or network connections.

          Knowledge check: What is the safest first response to an unfamiliar process in an authorized environment?

          Recap

          Systems contain layered components; processes are running programs; logs and telemetry preserve context; careful observation comes before disruptive action.

          Recommended next activity: Linux File Detective to practise safe, read-only inspection.

          SUPPLEMENTAL LESSON

          Incident Response

          Incident response is a coordinated process for preparing, detecting, containing, removing, and learning from security incidents.

          Learning objectives

          • Describe the incident-response lifecycle.
          • Separate validation, containment, eradication, and recovery.
          • Choose a safe response that preserves evidence and follows authorization.

          Why this matters in cybersecurity

          Rushed changes can destroy evidence or increase downtime. A shared process helps teams limit harm, communicate clearly, and document decisions.

          Important terminology

          Incident
          A security event that threatens confidentiality, integrity, or availability and requires response.
          Containment
          Limiting spread or impact while preserving the ability to investigate.
          Eradication
          Removing the confirmed cause after evidence is collected.
          Recovery
          Safely restoring service and monitoring for recurrence.

          The response lifecycle

          1. Prepare: define roles, contacts, tools, backups, and playbooks.
          2. Detect and analyze: validate evidence, scope affected assets, and assign severity.
          3. Contain: use an approved, proportionate action to limit harm.
          4. Eradicate and recover: remove the cause, restore safely, and monitor.
          5. Learn: document lessons and improve controls without blame.

          Practical example

          Simulation: monitoring confirms one workstation is contacting known malicious infrastructure. The responder records time and asset details, escalates through the playbook, and uses the approved isolation control. They do not wipe the device or publish unverified claims.

          A safe investigation command on an authorized Linux host might be date -u to record a consistent UTC timestamp; commands alone do not replace the response plan.

          Try It: order the response

          Place these ideas mentally in order: restore a clean service, validate an alert, isolate through an approved control. The safe order is validate, contain, then recover.

          Knowledge check: A confirmed workstation is communicating with malicious infrastructure. What is the best next step?

          Recap

          Responders validate, scope, contain, eradicate, recover, and learn. Evidence preservation, authorization, documentation, and proportionate action support every phase.

          Recommended next activity: SOC Alert Investigation to apply the process to simulated evidence.

          SUPPLEMENTAL HANDS-ON PRACTICE — NO CORE XP
          Reconnaissance
          Reconnaissance means gathering information to understand a system. Defenders use it to notice unnecessary exposure before it becomes a problem.
          Not completed
          

          Learning objectives
          Distinguish passive observation from active interaction, respect authorization and scope, and identify exposed information.
          

          Key terminology
          Passive reconnaissance: reviewing information already supplied. Active reconnaissance: interacting with a system to obtain information. Scope: the explicit boundaries of permission. Exposure: information available to others.
          

          Beginner explanation and safe examples
          Public information is not permission to test a system. In this simulation, read only the fictional records supplied below. Active checks require explicit approval; do not visit or probe real systems.
          

          Authorized scenario
          You are reviewing a fictional school’s supplied public inventory. Your authorization permits reading these records only. An outdated software label and an unnecessary staff contact may help outsiders infer system details.

Scope: review supplied records only; no scans, logins, or direct requests.

          Separate what the records reveal from what you are allowed to do.

          SUPPLEMENTAL HANDS-ON PRACTICE — NO CORE XP
          Network Analysis
          A packet is a small unit of network data. Source and destination addresses identify endpoints; ports identify services.
          Not completed
          

          Learning objectives
          Read a traffic table, identify protocols and endpoints, and support a cautious conclusion with evidence.
          

          Key terminology
          TCP: connection-oriented transport. UDP: datagram transport. ICMP: network status/error messages, without TCP/UDP ports. DNS: maps names to addresses, commonly port 53. HTTP: web requests, commonly TCP port 80; HTTPS commonly uses 443.
          

          Beginner explanation and safe examples
          One unusual row is a clue, not proof. Compare timing, repetition, direction, service, and the expected baseline. Private addresses here describe fictional hosts. Do not capture or contact real traffic.
          

          Authorized scenario
          A fictional workstation normally sends a DNS query followed by a web request. Compare that pattern with repeated connection attempts to a server administration service.
          

          Guided simulation: inspect the evidence
          Read the supplied records, then work through each decision below. Nothing is executed or sent over the network.
          SIMULATED TRAFFIC

09:00:02  10.0.0.20    10.0.0.80     TCP        80         HTTP GET /lesson
09:00:03  10.0.0.20    10.0.0.1      ICMP       —          status reply
09:01:00  10.0.0.99    10.0.0.10     TCP        22         60 attempts in 10 seconds; no approved maintenance

          Read the columns before interpreting the pattern.
          The last row repeats rapidly against port 22, unlike the DNS-then-web baseline.

          SUPPLEMENTAL HANDS-ON PRACTICE — NO CORE XP
          Linux Challenges
          Linux inspection connects users, files, permissions and processes. This exercise uses supplied outputs only: there is no terminal and nothing runs on your computer.
          Not completed
          

          Learning objectives
          Identify the current user, locate and inspect evidence, interpret permissions, and choose a safe next action.
          

          Key terminology
          User: an account identity. Group: a collection of accounts used for access control. Process: a running program with a PID. Permissions: read (r), write (w), execute (x) for owner, group and others.
          

          Beginner explanation and safe examples
          pwd shows the current directory; ls lists entries; cd changes directory; cat reads a file; grep selects matching lines; find locates files; whoami names the current user; id shows user/group IDs; ps lists processes. Example inspection sequence: pwd; ls; cd /training; cat notice.txt; grep "failed" /training/auth.log; find /training -name "*.log"; whoami; id; ps. These are explanations of fictional outputs, not commands to execute.
          

          Authorized scenario
          An authorized fictional training host has an unfamiliar notice file and an authentication log. Review the read-only outputs, preserve evidence and report concerns rather than changing files or stopping processes.

          Read the supplied records, then work through each decision below. Nothing is executed or sent over the network.

          SUPPLEMENTAL HANDS-ON PRACTICE — NO CORE XP
          Defensive Security
          A security alert is a signal to investigate. Logs record events; an indicator of compromise is an observable clue that may suggest unauthorized activity, not proof by itself.
          Not completed
          

          Learning objectives
          Build an event timeline, identify involved accounts and addresses, document evidence, and propose proportionate response.
          

          Key terminology
          Failed logon: rejected authentication. Successful logon: accepted authentication. Privilege change: altered access rights. Account creation: a new identity. Containment: approved steps to limit potential harm while preserving evidence.
          

          Beginner explanation and safe examples
          Correlate events rather than judging one alert in isolation. Check approved changes, account ownership and authentication context. Document timestamps, event IDs, actors, affected assets, observations and uncertainty.
          

          Authorized scenario
          You are an authorized analyst reviewing a fictional server. No account creation or privilege changes were scheduled. The record set may indicate account misuse; investigate through the incident-response plan.
          

          Guided simulation: inspect the evidence
          Read the supplied records, then work through each decision below. Nothing is executed or sent over the network.
          FICTIONAL AUTH/EVENT LOG — server demo-01
10:00 E101 failed logon account=demo-admin source=192.0.2.44
10:01 E102 failed logon account=demo-admin source=192.0.2.44
10:02 E103 successful logon account=demo-admin source=192.0.2.44
10:03 E104 account created actor=demo-admin new=backup-helper
10:04 E105 privilege change actor=demo-admin target=backup-helper group=administrators
Baseline: no approved account/privilege changes during this period.
          Reasoning hint
          Order the records, then correlate the repeated account and source with the later changes.
          E103 follows the failures; E104 and E105 create and elevate backup-helper.
          

          Step 1: Which timeline matches the evidence?




          

          Step 2: Which identity and source require investigation?




          

          Step 3: What supports concern?




          

          Step 4: What should the defender do next?




          

          

          Recap
          Write an evidence-based timeline, distinguish observation from inference, identify affected accounts, and preserve records before approved response.
